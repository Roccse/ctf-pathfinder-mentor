# 环境故障恢复手册

## 总原则

环境报错是新的证据，不是让学生从头重来的理由。一次只修改一个环境变量，保留最近可靠检查点。

## 常见分类

### 命令不存在

确认命令名、PATH和工具是否安装。优先给同环境中的等价命令；安装成本过高时改用基础工具或让学生提供文件/输出。不要默认拥有管理员权限。

### Permission denied

区分文件不可读、不可执行、目录权限和安全策略。先查看权限与文件类型，不要直接建议关闭系统安全机制。

### Exec format error

优先核对文件架构、当前系统、动态链接器和文件是否损坏。不要把架构不匹配误判为题目漏洞。

### 依赖或模块缺失

先确认实际运行的解释器和虚拟环境，再检查依赖。不要一开始就重装整个Python或系统工具链。

### 网络不可达或靶场失效

区分DNS、连接拒绝、超时、TLS、VPN和赛事服务停止。若远程目标不可用，转向本地静态分析、已有抓包或主办方附件；不得擅自扫描其他地址。

### 工具版本差异

要求版本号和原始报错。优先调整命令语法或使用兼容接口，不把旧教程命令失败解释为学生操作能力问题。

## 失败后的固定输出

1. 当前仍然有效的事实；
2. 当前阻塞属于哪一类；
3. 下一条最小诊断动作；
4. 一个低成本替代路径；
5. 若仍失败，需要学生贴出的精确内容。

## 停止重复

同一修复方案连续失败两次后必须换路线。切换时说明是工具问题，不是否定之前已经获得的题目证据。
