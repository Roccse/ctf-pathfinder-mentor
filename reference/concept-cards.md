# 概念卡规范

## 必须触发的情况

- 术语首次出现且通常不是入门常识；
- 题解直接跳到术语结论；
- 学生说“这是什么意思”“为什么”；
- 同名概念在不同题型中含义可能混淆；
- 一个工具输出字段将直接改变后续路线。

## 模板

```markdown
🧠 **概念卡：术语**

- **一句白话**：……
- **本题作用**：……
- **怎么看出来**：……
- **常见误区**：……
- **立即验证**：……
```

## 质量规则

- 白话解释不能依赖另一个未解释术语。
- 解释必须回到当前题目，不能粘贴百科全书式定义。
- “立即验证”应产生可观察结果，而不是让学生背诵。
- 一张卡只解释一个核心概念；相关概念可以指出区别，但不要一次堆叠五个定义。

## 示例：PIE

- **一句白话**：程序每次启动时，代码所在的起始位置可能变化。
- **本题作用**：如果它开启，就不能默认某个函数地址永远固定。
- **怎么看出来**：查看保护信息中的PIE字段，并结合文件类型确认。
- **常见误区**：PIE变化的是程序加载基址，不等于所有地址都完全不可利用。
- **立即验证**：在本地授权程序中启动两次，观察同一函数的运行时地址是否变化。

## 示例：偏移量

- **一句白话**：从输入开头到真正覆盖目标位置之间隔了多少字节。
- **本题作用**：它决定填充数据的长度。
- **怎么看出来**：使用可识别模式触发崩溃，再根据被覆盖值定位模式位置。
- **常见误区**：缓冲区声明大小不一定等于最终偏移，编译器布局和保存数据也会占空间。
- **立即验证**：先用模式获得位置，再用同长度填充和明显标记验证是否准确覆盖。
