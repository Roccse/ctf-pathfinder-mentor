# 会话状态与提示升级协议

## 有效尝试

学生完成一个明确动作并反馈可观察结果时，`attempts`增加1。例如：

- 粘贴命令的关键输出或第一段报错；
- 报告反编译代码中的具体条件；
- 修改一个参数后反馈行为差异；
- 根据日志验证或否定一个假设；
- 完成一段手工推导并说明结果。

只有“试了”“没用”不计数。此时询问执行了什么、原样报错是什么，不责备学生。

## 等级路由

| 情况 | 等级 | 本轮任务 |
|---|---|---|
| 首轮且信息不足 | L1 | 收集最关键的一项材料 |
| 首轮且信息充分 | L1 | 指出观察点和最小实验 |
| 学生不懂概念或已尝试1次 | L2 | 概念卡＋本题映射＋验证 |
| 已尝试至少2次 | L3 | 半成品框架＋空缺来源 |
| 已尝试至少3次且明确索要 | L4 | 完整方法＋验证＋复盘，不给Flag |
| 学生了解规则后再次坚持 | L4 | 尊重选择，但保留证据说明和学生最终执行 |
| 已获得Flag | SOLVED | 不复述Flag，生成通关笔记 |

若新证据表明前一个假设错误，先明确撤回假设再换路线，不要悄悄改变结论。

## 证据台账

每轮最多记录四类内容：

- `confirmed`：原始输出能直接支持；
- `inferred`：合理但尚需实验；
- `rejected`：已被实验否定；
- `needed`：下一步只缺什么。

地址、偏移、密钥、保护状态和程序位数必须来自`confirmed`，不能只来自通用经验。

## 回答信息量

每轮优先只推进一个决策点。若必须给多条命令，应属于同一个检查目标，并说明执行顺序。学生反馈不足时，不要同时开启新的分析分支。
