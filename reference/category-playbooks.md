# CTF题型路线

只阅读当前题型对应章节。路线用于组织证据，不代表每道题都必须执行所有步骤。

## PWN

1. 确认文件类型、架构、链接方式和运行条件；
2. 检查保护机制，并解释只会影响当前决策的字段；
3. 定位输入点、长度处理和关键调用路径；
4. 用崩溃、寄存器或栈证据验证控制位置，不猜偏移；
5. 根据保护与可用代码选择思路；
6. 先本地验证，再由学生决定是否连接赛事明确授权的服务；
7. 学生执行最终步骤并自行记录Flag。

## Reverse

1. 确认文件类型、架构、是否加壳及可运行条件；
2. 从字符串、导入函数和入口附近建立候选路径；
3. 定位输入处理和校验函数；
4. 将伪代码还原为输入—变换—比较的数据流；
5. 通过断点、日志或最小重写验证关键条件；
6. 让学生用自己的话解释校验逻辑，再完成最终输入。

## Crypto

1. 列出已知量、未知量和数据格式；
2. 判断是编码、经典密码、现代密码误用还是数学弱点；
3. 明确依赖的安全假设，不因看到大整数就断言RSA；
4. 用最小样例验证公式和字节序；
5. 编写可重复的小脚本，打印中间量；
6. 由学生完成最终计算并检查Flag格式，但不在回复中复述。

## Web

仅限授权靶场。先明确目标域名或本地服务来自比赛/课程，再进行：

1. 观察正常请求与响应；
2. 识别路由、参数、身份、会话和输入处理；
3. 每次只改变一个参数，比较行为差异；
4. 根据响应证据验证假设，不进行无范围扫描；
5. 优先说明漏洞成因与修复方法；
6. 最终验证只在授权目标内进行。

## Forensics

1. 保留原文件并计算摘要；
2. 识别真实文件类型和容器结构；
3. 检查元数据、时间线、嵌入内容或流量会话；
4. 每个提取物记录来源位置；
5. 建立证据链，避免只凭文件名下结论；
6. 由学生完成最终拼接或识别。

## Misc

先判断是否实际属于编码、隐写、协议、脚本分析或信息检索，再转入最接近的路线。若无法分类，优先取得一个能缩小范围的文件类型、输出特征或题目约束。
